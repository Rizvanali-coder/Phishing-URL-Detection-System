## 1. Overview

This project trains and evaluates machine-learning classifiers using the UCI Machine Learning Repository's **Phishing Websites** dataset. It compares a simple baseline with tree-based models, uses a stratified hold-out test set, reports phishing-focused metrics, and saves the best model pipeline.

**Important scope note:** the selected UCI dataset contains 30 pre-computed website/URL-related features, not raw URL strings alone. The trained model therefore predicts from those feature columns. It does not safely fetch or browse an arbitrary live URL, and it should not be represented as a real-time URL scanner without a separately validated feature-extraction pipeline.

## 5. Evaluation design

The notebook uses a stratified 80/20 train/test split with a fixed random seed. Candidate models are compared using accuracy, precision, recall, F1-score, ROC-AUC, confusion matrix, and a classification report. Cross-validation is run on the training split only. The test split is held back for final evaluation.

Because phishing false negatives can be costly, pay particular attention to **phishing recall** and the confusion matrix—not accuracy alone. Results are generated by executing the notebook; this package does not claim unrun or fabricated scores.

## 7. Limitations and responsible use

- The UCI dataset was donated in 2015, so it may not represent current phishing campaigns.
- A random split can overestimate performance when related websites or collection patterns appear in both splits. A time-based or domain-grouped evaluation is recommended for further work.
- The dataset uses pre-computed features. This model is not a browser, URL reputation service, or guarantee that a website is safe.
- Never open suspicious URLs just to test them. Use isolated, authorized lab environments and trusted threat-intelligence sources.
- A false “legitimate” result does not prove a site is safe. Verify links through independent channels and avoid entering credentials on uncertain sites.

## 8. Suggested extension work

1. Evaluate on a newer, independently sourced dataset.
2. Use domain-grouped or time-based splits to reduce leakage.
3. Add calibration and threshold analysis based on false-negative cost.
4. Build a separately tested raw-URL feature extractor, documenting which features are URL-only versus webpage/network-derived.
5. Add model cards, data versioning, and monitoring for distribution drift.
